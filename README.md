# Production ML Maintenance Service

A reproducible production-oriented portfolio project: train a failure-risk classifier, serve predictions through FastAPI, persist prediction records in SQLite, inspect feature drift, and practise version promotion and rollback. Start with **START_HERE_WINDOWS.md**.

## Scope and honesty
Data is generated by a documented synthetic probability process in mlops/core.py. This is an operations exercise, not a real-world failure prediction benchmark or a machine-safety tool. The target is sampled probabilistically, and the test set is held out before model fitting. Preprocessing is fitted only on training data and saved in the same pipeline. Metrics cannot demonstrate performance on real machinery.

## Components
| Component | Implementation |
| --- | --- |
| Reproducible training | Fixed seed, stratified holdout, Pipeline, data hash |
| Evaluation | Average precision, ROC AUC, prevalence, confusion matrix |
| Serving | FastAPI, bounded inputs, explicit model version |
| Audit | SQLite successful prediction records with IDs and timestamps |
| Monitoring | Success count, mean inference time, feature mean-shift report |
| Release operations | Immutable versions, atomic active pointer, restart, rollback |
| Verification | Integration tests, GitHub Actions, Docker image build |

## Portable quick start (Python 3.12)
```sh
python -m pip install -r requirements.txt
python -m mlops.cli train --version v1
python -m mlops.cli promote v1
python -m unittest discover -s tests -v
python -m uvicorn mlops.api:app --host 127.0.0.1 --port 8000
```
Windows users should use the explicit virtual-environment executable in START_HERE_WINDOWS.md.

## Operational boundaries
Single-instance educational service; SQLite and a local filesystem registry are chosen for inspectability. There is no authentication, automated alert delivery, true-label feedback, scheduled retraining, automated quality gate, request-rate limiting, or distributed release coordination. Do not expose this API for sensitive data or real machinery decisions. /metrics excludes unsuccessful requests. Inference latency excludes database and network overhead. Monitor sufficient_samples before interpreting drift; drift is not accuracy degradation. Train commands are intended for one operator at a time.
